# 2026-09-29: defaults for the open roadmap questions

Context: the competitive/API roadmap (`.analysis/competitive-10x/ROADMAP.md`) left eight questions open. The user asked for all of it to proceed. Per CLAUDE.md ("decide, don't ask", except spend, destructive actions and run scope), these defaults are chosen here and stated so they can be reversed. Only the paid-vendor choice is left as a recommendation, because it commits money.

| # | Question | Decision | Reversible how |
|---|---|---|---|
| 1 | OQ-3 paging vendors | **Push: APNs and FCM directly**, as architecture.md §Alerting specifies. No vendor, no cost. The generic "push provider" endpoint is replaced by direct adapters. **SMS and voice: recommendation only.** N1.2 requires two *different* vendors. Recommended: Twilio Programmable Messaging for SMS and AWS End User Messaging (Voice) for voice. They are in different companies and failure domains, both usage-priced, and the architecture estimates about $60–95/month combined. The port/adapter shape keeps the choice to config. | Config change per channel; needs budget sign-off before signing up. |
| 2 | OQ-25: does halt cancel scheduled voice calls? | **No, by default.** Halt stops *future tones* and automatic mutual aid; a voice call already scheduled for an unanswered tone still goes out. This matches architecture §1.3a and today's behaviour. It will become a department setting (`haltCancelsPendingVoice`, default `false`) so a chief can choose otherwise. | Department config. |
| 3 | #2 CAD surface | Build **two deterministic ingress paths**: SES inbound email (works with any CAD that can email) and a signed JSON webhook. The parser is per-source config, compiled and versioned, and fails open to raw text. EIDO or vendor CAD APIs come later as adapters. | New adapters are additive. |
| 4 | AI data residency | **Strict: us-east-1 only.** Use in-region Bedrock model IDs, not the "US" cross-region profile, until someone confirms NERIS residency means "the US" rather than the region. | Swap the model ID to the US inference profile. |
| 5 | Prevention scope (CT fire marshal) | **Defer** permits, fee invoicing and code-enforcement workflows. Build walk-throughs, pre-plans, hydrants and CRR, plus read-only sharing with the fire marshal. | Add later if Nichols owns code inspections. |
| 6 | Architecture amendments | **Approved to build:** assist-service (the only role allowed Bedrock/Transcribe, and explicitly denied to the alerting role); live service (realtime, read-only over the outbox); presence plane (advisory only; the ladder never depends on it). **Deferred** until the chief weighs in: the `station` alert channel, the person record across departments, and unauthenticated public writes. | Each deferred item is additive later. |
| 7 | Entitlements | File **Critical Alerts (#4)** and **CarPlay public-safety** applications now, because Apple's lead time is the long pole. This is a human step and needs the department's Apple developer account. | n/a |
| 8 | Nichols specifics (§12-81w thresholds, CGS 7-148 pension, Chief360 export) | Build the benefit engine configurable with a `TRUMBULL_12_81W` template. Thresholds are entered by the department and are not assumed. | Data, not code. |

**Build order:** Phase 0 blockers first (authorizer done; direct push; config and hosting), then the Phase 1 parity items, one alerting-path change at a time. Every alerting-path change gets the end-to-end chain review before merge.
